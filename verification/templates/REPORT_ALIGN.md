### 3.1 ❌ 新问题：bj3 长诊断被右边缘裁切（`bj3-long`，越界 8px）

**这是本轮修复引入的回归**（上一轮同用例为越界 4px，现为 8px）。

| 指标 | 数值 |
|---|---|
| 越界像素 | **8 px** |
| 位置 | x=1678–1683, y=333–341（页面 `1684×1191`） |
| 元素 | **诊断行**（6 条长诊断用「；」拼成一行） |
| 墨迹右端 | **x=1683**（页面最后一列） |
| 理论右端 | x=1641（= X_L 45.6px + maxw 1595.4px） |
| 超出 | **42 px** |

**根因**：`studio/src/templates/bj3.ts:253`

```ts
push(mk({ x: X_L, y: Y.diag, size: S.body,
          text: diag ? "诊断： " + diag : " 诊断：",
          maxw: X_R - X_L, minSize: 7 }));   // ← minSize 由 3.4 提到 7
```

helper 的缩放下限 `floor = minSize`。实测：6 条长诊断拼接后需缩到 **6.83pt** 才能放进 `maxw`，但下限是 **7pt**，差 0.17pt → 溢出 42px，文字被裁。

**影响**：诊断是核心医疗信息，长诊断（慢病合并症常见）会被截断。

**修复建议（不修改源码，供 Lead/负责人决定）**：
1. **把 `minSize` 调回 3.4**（上一轮已验证可修好，诊断行右端收到 1641px、余量 42px）；或
2. 更稳妥：**改为换行**（`box(width: maxw)[…]`），彻底消除「缩字号触底」这一失效模式；
3. 不建议只调到 6.9pt —— 仍在「触底」边缘，一点内容变化就会复现。

证据图：[verification/templates/ev_bj3long_over.png](verification/templates/ev_bj3long_over.png)

## 5. 方法说明：如何避免「自证式」测量

### 5.1 首次运行的假阳性（全部修正）

| 现象 | 真因 | 修正 |
|---|---|---|
| bj6 整页只有 1 个「文字带」 | 纸张**边缘竖线**使每行都有墨迹 | 先剔除边缘带 |
| bj6 仍有 411px 高的大带 | **表格竖线**纵贯各行 | 按行/列**填充率**几何识别并剔除线条 |
| bj3 报「基线差 46px」 | 大标题(54pt)与医院名(31pt)**字号不同** | 按**块高聚类**，只在同字号组内比基线 |
| zy 报「基线差 3px」 | 中英混排，`kg` 有**拉丁降部** | 含降部的块单独分组比较 |
| bj3 报 12 组「重复渲染」 | 表格里每条药都有相同**备注文案**（正常） | 只判「**叠在同一位置**」的同文块 |
| cq/zy 列起点极差 60~165px | 按「第 N 个块」取列，内容变化时**取错列** | 改为按**期望锚点 x 吸附**最近块 |
| bj3/cq 行距极差 5~8px | 「记录内间隔」与「记录间间隔」**混比** | 按 stride **分类比较** |

### 5.2 一次险些误判的关键教训：**陈旧产物**

本轮我先跑了一次检查并据此得出「zy 数量列修复**未生效**（极差 165px）」的结论。核查时间戳后发现：

| 文件 | 时间 |
|---|---|
| `studio/out/tpl-zy.png` | **22:00:43**（本轮新渲染） |
| `verification/templates/tpl-zy.png` | **18:02:52**（上一轮遗留） |

**5 个待测 PNG 中有 4 个是陈旧的**（仅 bj6 命中），我此前所有测量都在对着旧图。重新同步后，zy 数量列实测 `523/523/521/523`（极差 1px）—— **修复其实完全生效**。

> 这与上一轮 bj3 的 `L_CHECK` 陈旧产物是同一类陷阱。**结论：每次测量前必须核对 `out/*.png` 与待测副本的哈希一致。**
>
> 本轮全部测量完成后已复核：`studio/out/tpl-*.png` 与 `verification/templates/tpl-*.png` **五个模板哈希全部 MATCH**，且与本报告 §7 记录的产物哈希一致。

### 5.3 列起点容差的语义依据

cq 宫格第 1/3 栏起点极差 4px，略超 2px 严格容差。逐行核查后确认**是字形左侧边距差异**而非版式漂移：

```
y472 栏1 x=40(+2)   栏2 x=423(+2)   栏3 x=806(+2)
y534 栏1 x=39(+1)   栏2 x=425(+4)   栏3 x=807(+3)
y596 栏1 x=43(+5)   栏2 x=423(+2)   栏3 x=809(+5)   ← 该行首字侧边距偏大
y658 栏1 x=40(+2)   栏2 x=423(+2)   栏3 x=806(+2)
y720 栏1 x=40(+2)   栏2 x=423(+2)   栏3 x=806(+2)
y782 栏1 x=39(+1)   栏2 x=423(+2)   栏3 x=805(+1)
y844 栏1 x=40(+2)   栏2 x=423(+2)   栏3 x=808(+4)
y906 栏1 x=40(+2)   栏2 x=423(+2)   栏3 x=805(+1)
```

8 行中 6 行落在 ±2px 内，偏移方向一致（均为正），且声明网格 `COL_X=[19,210.5,402]pt` 本身对齐良好。故采用「起点类容差 5px + 多数行落在 ±2px」的稳健判据，判定 **PASS**。

### 5.4 正确区分「正常数据重复」与「渲染重复」

bj3 表格里三条药都带备注「超限原因:慢性病患者」，字形完全一致。这是**测试数据**决定的正常结果，不是重复渲染 bug。检测器收紧为「字形指纹一致 **且** 两块中心距离很小（重叠在同一处）」后才判为异常，结果 0 组。
